## 2. 滚动阶段

按顺序推进，每阶段验证无回归后进入下一阶段：

| 阶段 | 范围 | 验证 |
|---|---|---|
| 1. 开发者构建 | 复制非生产用户数据 | CJK 搜索可用、英文搜索无回归 |
| 2. 内部 QA | Windows x64 + macOS arm64 | 升级路径、迁移日志、性能 |
| 3. 内部小规模灰度 | 少量内部用户 | 无迁移问题、无召回回归 |
| 4. 更广内部发布 | 内部全量 | 汇总本地迁移日志和支持反馈中的迁移失败案例 |
| 5. 生产发布 | 全量用户 | 支持评审通过后 |

## 3. 升级前备份

**首次生产迁移前必须备份：**

```bash
# 方式一：SQLite 官方备份（推荐；需要系统已安装 sqlite3）
sqlite3 engram.db ".backup 'engram-backup-YYYYMMDD.db'"

# 方式二：运行时完全停止后复制数据库文件
# 1. 停止 engram 进程
# 2. 确认进程已退出；复制 engram.db
# 3. 若关闭后仍存在 engram.db-wal / engram.db-shm，须将它们与主库作为同一快照一并保存
# 4. 记录原运行时版本与数据库路径
```

**禁止**：运行时在线状态下裸复制数据库文件（WAL 未合并会丢数据）。

**诊断元数据**：备份文件名包含原版本（如 `engram-backup-20260810-v1.20.0.db`）。

**隐私**：备份文件含记忆内容，不得写入日志或上传。

## 4. 回滚策略

**应用回滚与数据回滚分离：**

| 场景 | 操作 |
|---|---|
| 应用层问题（UI、集成） | 回滚应用版本即可，无需动数据 |
| 迁移后数据问题 | **禁止原地降级**。停止 engram，恢复迁移前备份 + 旧版运行时 |
| 迁移失败（启动即挂） | 事务回滚保证旧库可读；修复后重启重试 |

**升级路径**：

```text
v1.20.0 (upstream, unicode61)
   ↓ 首次启动自动迁移（trigram 重建，事务原子）
v1.20.0-zhiyuan.1 (fork, trigram)
   ↓ 禁止原地降级 ⛔
v1.20.0 (upstream)  ← 必须恢复备份
```

## 5. 发布阻塞项

出现以下任一情况即阻塞发布：

- 迁移导致基表数据丢失或损坏
- CJK Recall@8 < 95%
- 英文搜索回归超容忍度
- 已删除/跨项目记忆可被检索
- 资产 checksum 或来源不可验证
- 任一支持平台缺可用二进制
- 短词查询延迟无界（不支持的数据规模）

## 6. 升级后验证（灰度期）

- [ ] 迁移日志仅两条（开始/完成，含行数与耗时）
- [ ] 首次启动迁移耗时在可接受范围（10k 行 < 数秒）
- [ ] CJK 搜索命中预期记忆
- [ ] 英文搜索排序无感知变化
- [ ] 软删除记忆不可检索
- [ ] 重启后不重复迁移
